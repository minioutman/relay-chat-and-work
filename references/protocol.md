# 接力进度文件 (Relay Progress) 规范

长任务的所有接力状态统一存到工作区,以便跨会话续接。
默认存 `/var/minis/workspace/relay-work/` 下,每个任务一个文件。

## 文件命名

`/var/minis/workspace/relay-work/<task-slug>.md`

`<task-slug>` 用任务标题的简短英文/拼音小写,词间用连字符。
示例:`relay-book-20chapters.md`、`relay-clean-500data.md`

## 文件内容结构

```markdown
# 任务: <标题>
# 目标: <一句话说清楚最终交付物>
# 创建: <挂起的最后状态日期>
# 当前状态: 【进行中 | 等待确认 | 已完成】

## 计划 (总览)
- [ ] 阶段1: <阶段名> —— <交付物>
- [ ] 阶段2: <阶段名> —— <交付物>
- [ ] 阶段3: <阶段名> —— <交付物>

## 阶段进度
### 阶段1: <阶段名>  [✓ 已完成]
<该阶段做了什么、产出文件在哪、有无遗留问题>

### 阶段2: <阶段名>  [进行中 / 未开始]
<备注>

## 下次续接点 (RESUME POINT)
<具体写清楚: 当前做到哪、下一步从哪开始、有什么上下文/变量需要记住>
```

## 状态流转规则

- 每个阶段的勾选状态用 `[x]` / `[ ]` 表示,随进度实时更新文件。
- 每完成一个阶段,立即更新文件:「阶段进度」加一条、勾掉计划里的对应项、重写「下次续接点」。
- **续接点(RESUME POINT)是核心**——必须具体到"下一步该干嘛、从哪个文件/哪一行接、有哪些中间结果可用",保证下次读文件就能无缝接上。

## 自动推进与等待确认

- 阶段之间默认**自动推进**:上一个阶段产出满足阶段标准(count/验证通过)就直接开下一个阶段。
- 遇到以下情况才停下来「等待确认」:
  1. 阶段产出需要用户拍板(比如改动了用户的东西)
  2. 方向有分歧、有多种合理选择
  3. 有副作用/不可逆操作(删除、覆盖、对外发消息)
  4. 阶段标准无法满足且不知道怎么办
- 停下时,在「当前状态」写 `等待确认`,保留续接点,然后告知用户"进度已存档,回一句就能继续"。

## 跨会话续接

用户下次说「接着干」「继续xx」时:
1. 读对应任务文件
2. 看「当前状态」和「下次续接点」
3. 从续接点直接继续,不重复已完成的阶段
